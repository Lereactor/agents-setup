# Голосовые сообщения как триггер для shopping/grocery — дизайн

Дата: 2026-09-18. Статус: реализовано в `scripts/shopping-listener-worker.js`,
ожидает деплоя (см. `docs/SETUP-GUIDE.md`, раздел 6.7).

## Задача

Лев хочет отправлять голосовые сообщения в Telegram и чтобы система понимала
русскую речь и маршрутизировала их так же, как текст: если в сообщении есть
слово "вкусвилл" — идёт в `grocery`, если "куп"/"заказ"/"найд"/etc — в
`shopping`.

## Почему в Cloudflare Worker, а не в самих Routine

Воркер (`scripts/shopping-listener-worker.js`) уже единственная точка входа
для Telegram-вебхука и уже содержит всю логику определения target по
триггер-словам (`detectTarget`). Делать распознавание речи внутри самих
Routine означало бы: либо дублировать эту логику в промптах обоих агентов,
либо всегда файрить оба и давать им самим решать — оба варианта хуже.
Вместо этого воркер: скачивает голосовое, транскрибирует, прогоняет
транскрипт через ту же `detectTarget`, и файрит нужную Routine с уже готовым
текстом — Routine не отличает голосовое от обычного текстового сообщения.

## Выбор STT-движка

**Cloudflare Workers AI (`@cf/openai/whisper-large-v3-turbo`)** — без новых
аккаунтов/ключей, тот же Cloudflare-аккаунт, где уже живёт воркер. Модель
поддерживает вход `ogg` (формат голосовых Telegram — Opus в OGG-контейнере)
и параметр `language` для форсирования русского (важно короткие бытовые
фразы вроде "вкусвилл, купи молоко" не должны уходить в автоопределение
языка и путаться).

Стоимость: бесплатный лимит Workers AI — **10 000 нейронов/день**, сбрасывается
каждый день в 00:00 UTC. Whisper large-v3-turbo — ~46.6 нейрона/минуту аудио,
то есть бесплатно помещается 200+ минут распознавания в день — с огромным
запасом для личного использования, отдельно платить не придётся.

Альтернатива (OpenAI Whisper API) отклонена — лишняя зависимость и ключ для
хранения без видимого выигрыша в качестве для коротких бытовых фраз.

## Позиция триггер-слова во фразе

Решено: как и с текстом — триггер-слово может быть **где угодно** во фразе,
не обязательно первым словом. Используется та же функция
`matchesTriggerWords`/`detectTarget`, что и для обычного текста — никакой
отдельной логики для голоса.

## Подтверждение получения (ack)

Раньше бот молчал до самого ответа агента (который может занимать десятки
секунд — особенно `shopping`, который ходит в веб-поиск). Решено: **для
всех типов сообщений** (текст, фото, голос — единый вход через один и тот же
`fetch()`, других "каналов" в системе нет) сразу слать подтверждение в чат,
до того как Routine начнёт отвечать:

- Голосовое: `🎙️ Понял: "<транскрипт>" — передаю <ВкусВиллу/Shopping-агенту>.`
  (совмещает показ расшифровки — на случай ошибок распознавания, особенно
  названий товаров — и сам факт "принято в работу")
- Текст/фото: `✅ Принял, работаю…`

Ack отправляется **синхронно внутри одного `ctx.waitUntil`, до вызова
`triggerRoutine`** — иначе при параллельном запуске ack мог бы прийти
позже собственного ответа агента, если Routine отработает быстро.

## Обработка ошибок

- **Транскрипция упала** (сбой скачивания файла, ошибка Whisper) или
  **пустой транскрипт** → `⚠️ Не расслышал голосовое — попробуй ещё раз или
  напиши текстом.` Routine не запускается.
- **Транскрипт есть, но без триггер-слова** → показываем расшифровку и
  объясняем, что не поняли адресата: `🎙️ Понял: "<транскрипт>" — но не
  понял, кому это адресовано (скажи "вкусвилл" или "купи"/"закажи"/"найди").`
- Голосовые от ботов уже отсекаются существующей проверкой `is_bot` раньше
  по коду — новый путь её не обходит.
- Свой `sendMessage` (ack/ошибка) — исходящий вызов Telegram API, не новый
  update, так что не может сам себя зациклить через `is_bot`-проверку.
- Долгие голосовые не ограничиваются искусственно — практический лимит
  задаёт сам бесплатный дневной лимит Workers AI, которого с большим
  запасом хватает на голосовые заметки.

## Новые требования к инфраструктуре

- Новый секрет воркера: `TELEGRAM_BOT_TOKEN` (нужен для `getFile` + скачивания
  аудио + `sendMessage`). Добавляется через `/secrets` API-эндпоинт — не
  трогает существующие bindings/секреты (тот же паттерн, что уже
  использовался в разделе 6.6 для grocery-токенов).
- Новый binding воркера: `AI` (Workers AI) — добавляется через дашборд
  (Settings → Bindings → Add → Workers AI), без API-токена. Через API
  безопасно добавить binding, не зная текущих значений существующих
  secret_text-биндингов, не получилось надёжно подтвердить (см. неоднозначность
  вокруг `keep_bindings` в публичной документации Cloudflare на момент
  написания) — поэтому для ЭТОГО одного шага выбран путь через дашборд, а не
  через curl, чтобы не рисковать существующими секретами `ROUTINE_TRIGGER_*`.
- Код воркера обновляется тем же безопасным `/content`-эндпоинтом, что и в
  разделе 6.6 (не трогает bindings/секреты).

## Инциденты при первом деплое (2026-09-18)

Протестировано вживую через `?debug=1` на реальном голосовом сообщении из группы
("вкусвилл, купи творог", 2 сек) — после двух фиксов ниже всё заработало
корректно (`target: grocery`, транскрипт "Вкус Вилл. Купи творог.", Routine
запустилась).

**Инцидент 1 — неверный формат `audio` для `whisper-large-v3-turbo`.** Первая
версия слала `audio: Array.from(new Uint8Array(bytes))` (по образцу тьюториалов
для старой модели `@cf/openai/whisper`) — модель отвечала `AiError 5006: Type
mismatch of '/audio'` с разным (и противоречивым от попытки к попытке) списком
"допустимых" типов в сообщении об ошибке. Официальный тьюториал по chunking-
транскрипции показывает другой формат для этой конкретной модели: **`audio` —
base64-строка**, не массив байт. Исправлено: `btoa(String.fromCharCode(...bytes))`
кусками по 0x8000 (не `Buffer` — потребовал бы `nodejs_compat` flag, которого нет).

**Инцидент 2 — Whisper пишет "ВкусВилл" с пробелом.** Реальная расшифровка
пришла как "Вкус Вилл. Купи творог." — простой `.includes('вкусвилл')` не
сработал из-за пробела, сообщение улетело в `shopping` вместо `grocery`.
Исправлено: `matchesTriggerWords` теперь сначала нормализует текст (убирает всё,
кроме букв/цифр, приводит к нижнему регистру) — правило применяется одинаково
к тексту и к голосу, отдельной ветки для голоса не заводили.

Обе правки уже в финальной версии `scripts/shopping-listener-worker.js`.
