# Дизайн: агент-покупки (Ozon / Яндекс.Маркет, по ключевому слову)

Дата: 2026-08-20
Статус: спроектирован, не настроен (см. открытые вопросы и порядок настройки)

## Контекст

Третий агент из системы (см. `agents-setup-brief.md`, идея №1 «Агент-покупки»).
Отличие от первых двух (`news-digest`, `watchdog`): те работают по расписанию,
этот должен реагировать на конкретное сообщение в Telegram — ключевое слово
(«купи», «купить», «найди», «закажи» и т.п.), в том числе с приложенным фото.

У Routines нет нативного триггера «пришло сообщение в Telegram» (см. проблему,
уже описанную в брифе для нереализованного агента-заправок, идея №4). Решение
здесь и там одинаковое: лёгкий слушатель, который дёргает Routine через
API-триггер, когда что-то произошло.

Ни у Ozon, ни у Яндекс.Маркета нет открытого API — используем веб-поиск внутри
Routine (тот же подход, что в `news-digest`), а не браузерную автоматизацию:
проще, надёжнее, не требует MCP-сервера/хостинга внутри облачного Routine.

## Архитектура: два звена

**Звено 1 — слушатель (Google Apps Script веб-хук, без ИИ).**
Telegram сам присылает туда каждое входящее сообщение (webhook), включая
`business_message` из личных чатов через секретарский режим на Premium-
аккаунте. Слушатель грубо фильтрует по корням слов и либо дёргает Routine,
либо (в подавляющем большинстве сообщений в группе) не делает вообще ничего —
дорогой LLM-агент не должен запускаться на каждое сообщение.

**Звено 2 — Routine `shopping-agent` (разовый запуск с LLM).**
Получает параметры от слушателя, сам решает, реальная ли это просьба найти
товар, ищет на Ozon и Яндекс.Маркете, сравнивает и отвечает в Telegram.

## Звено 1: слушатель — `scripts/shopping-listener.gs`

По образу `scripts/log-sheet.gs`. Логика `doPost(e)`:

1. Распарсить `e.postData.contents` как Telegram Update (JSON).
2. Достать сообщение: `update.message` (группа) или `update.business_message`
   (секретарский режим — оба разбираются одинаково, поле апдейта разное).
3. Определить текст-кандидат для проверки триггера:
   - `message.text` — обычное текстовое сообщение;
   - `message.caption` — подпись к фото в том же сообщении;
   - если у `message` нет ни текста, ни подписи, но есть
     `message.reply_to_message.photo` — взять текст из `message.text` (это
     реплай на более раннее фото с текстом-командой).
4. Проверить текст-кандидат на корни (регистронезависимо, простой substring
   `includes()`, без морфологических библиотек): `куп`, `заказ`, `найд`,
   `buy`, `order`, `find`.
5. Если совпало — собрать параметры и вызвать Routine API-триггер:
   - `chat_id`
   - `message_id` (для ответа реплаем)
   - `business_connection_id` (если сообщение из `business_message`, иначе
     пусто)
   - `text` (сам текст/подпись, что бы ни сработало на шаге 3)
   - `photo_file_id` — `file_id` фото наибольшего разрешения из
     `message.photo` либо `message.reply_to_message.photo`, если есть
6. Если триггер-слов нет — выйти, ничего не логировать и не вызывать
   (не запуск агента, а обычный шум чата).

Секреты (URL+токен Routine API-триггера) — в Script Properties, как уже
сделано для `SECRET_TOKEN` в `log-sheet.gs`; тот же файл `sheets_api.txt`
или отдельный аналогичный, не в git.

## Звено 2: промпт Routine `shopping-agent`

Вход: `${CHAT_ID}`, `${MESSAGE_ID}`, `${BUSINESS_CONNECTION_ID}` (может быть
пусто), `${MSG_TEXT}`, `${PHOTO_FILE_ID}` (может быть пусто).

```
Ты — агент-покупки. Тебя вызвали по одному конкретному сообщению из Telegram.

1. Прочитай ${MSG_TEXT} целиком (не только триггер-слово) и реши: это
   реальная просьба найти/купить конкретный товар, или слово попало
   случайно (обсуждение не по теме, слишком расплывчато — например просто
   «купи» без указания что). Если не похоже на реальный запрос — сразу
   переходи к шагу 6 со status=skipped, в Telegram НИЧЕГО не пиши.

2. Если ${PHOTO_FILE_ID} не пусто:
   - вызови getFile через Bot API, получи file_path
   - скачай файл по прямой ссылке
     https://api.telegram.org/file/bot${TELEGRAM_BOT_TOKEN}/{file_path}
   - посмотри на изображение, опиши товар (категория, цвет, материал,
     бренд/модель если видно, отличительные детали)
   - это описание + любой текст из ${MSG_TEXT} (бюджет, цвет, размер и
     т.п.) вместе формируют поисковый запрос

3. Через веб-поиск найди этот товар отдельно на Ozon и на Яндекс.Маркете.
   Для каждого найденного варианта постарайся получить: цену, наличие,
   срок доставки (если виден), рейтинг/количество отзывов, прямую ссылку.

4. Выбери топ-2-3 варианта, балансируя цену/рейтинг/наличие — не всегда
   самый дешёвый, если у него плохой рейтинг или нет в наличии, объясни
   почему всё равно (или почему нет) его выбрал.

5. Отправь ответ в Telegram Bot API sendMessage, ОБЯЗАТЕЛЬНО с
   reply_to_message_id=${MESSAGE_ID}, chat_id=${CHAT_ID}, и
   business_connection_id=${BUSINESS_CONNECTION_ID}, если оно не пусто.
   Формат:

   🛒 {что искали}

   1. {название} — {цена} ₽, {Ozon/Я.Маркет}, ★{рейтинг} ({N} отзывов), {наличие/срок}
      {ссылка}
      {1 фраза почему хороший вариант}

   2. ...

   💡 {краткая рекомендация: что бы взял сам агент и почему}

   Если поиск не дал внятных результатов — короткое сообщение об этом
   вместо молчания.

6. Залогируй запуск на Sheets-вебхук (как остальные агенты):

   curl -s -L -X POST "${SHEETS_LOG_URL}" \
     -d "token=${SHEETS_LOG_TOKEN}" \
     -d "agent=shopping" \
     -d "status=success|skipped|error" \
     -d "timestamp=$(date -u +%Y-%m-%dT%H:%M:%SZ)"
```

Для `watchdog` изменений не требуется — он уже рассчитан на агентов без
заранее известной нормы (просто показывает их количество без оценки, см.
`2026-08-18-watchdog-agent-design.md`, шаг 4).

## Открытые вопросы (не проверить заранее)

- **Секретарский режим (Business Connection)** — ни разу не использовался,
  нужно на месте проверить, что Bot API вообще получает `business_message`
  для личных чатов, а не только сообщения в группе.
- **Формат вызова Routine через API-триггер** — какие параметры и как
  передавать (query string vs JSON-тело, как они становятся доступны
  промпту) — не использовался ни в одном из первых двух агентов (они только
  по расписанию), разобраться при настройке.
- **Список корней-триггеров** — стартовый набор, точность (ложные
  срабатывания/пропуски) проявится только на реальных сообщениях за первую
  неделю, тогда и скорректировать.

## Порядок настройки

1. Проверить секретарский режим: отправить тестовое сообщение в личный чат
   с ботом-секретарём, убедиться, что оно приходит (временный `getUpdates`
   или тестовый вебхук)
2. Создать Apps Script проект со слушателем, задеплоить как Web App,
   зарегистрировать через `setWebhook` (`allowed_updates` включая
   `business_message`)
3. Создать Routine `shopping-agent` с промптом выше, разобраться с
   API-триггером и параметрами
4. Прогнать вручную три сценария: (a) текстовый запрос в группе, (b) фото
   с подписью «купи», (c) сообщение с «купить», не относящееся к товару
   (должно тихо промолчать)
5. Понаблюдать неделю за логом в Sheets, скорректировать список
   триггер-слов при необходимости

Полный пошаговый рантайм-чеклист (создание бота, вебхука, Routines и т.д.)
ведётся отдельно и кумулятивно в `docs/SETUP-GUIDE.md`.
