## Контекст

Шестой агент в системе (после `news-digest`, `watchdog`, `shopping`,
`grocery`). Туту выложил официальный MCP-сервер `https://mcp.tutu.ru/mcp`
(Streamable HTTP, без авторизации): поиск ЖД, авиа, автобусов, электричек,
отелей и мультимаршрутов, детали предложения, схема мест, ссылка на
оформление. Оплаты через MCP нет — пользователь всегда платит сам на Туту.
Aviasales официального MCP не имеет (только сторонние stdio-серверы на
Travelpayouts API, требуют хостинга) — поэтому Туту.

Схема — ровно как у `grocery`: account-level коннектор + `permitted_tools`
(см. Инцидент 3 в `2026-09-17-grocery-agent-design.md`), общий Cloudflare
Worker-слушатель, отдельный Routine с API-триггером.

## Как это выглядит для пользователя

Главный принцип — **один вопрос → один готовый ответ**. Routine не помнит
прошлые сообщения (каждый вызов независим), поэтому диалог «какие даты?» →
«а откуда?» → «беру второй» не работает. Вместо этого:

- Пишешь как человеку: «билет в Питер на субботу», «поезд Москва Казань 15
  октября туда-обратно», «самолёт в Сочи на выходные на двоих», «отель в
  Казани с 20 по 22», «электричка до Сергиева Посада завтра утром».
- Чего не хватает — агент **не переспрашивает**, а подставляет разумное
  значение и честно пишет это в ответе (строка «Считал: …»), чтобы можно было
  поправить следующим сообщением:
  - откуда — Москва;
  - когда — завтра (если «на выходные» — ближайшая суббота);
  - сколько — 1 взрослый;
  - отель без дат выезда — 1 ночь;
  - вид транспорта не назван — между городами ищет и поезд, и самолёт.
- В ответе 3 варианта (по 2 + 1, если сравнивались поезд и самолёт), и у
  **каждого своя ссылка на покупку** (`create_checkout_link`). Нажал — открылся
  Туту на выборе мест/корзине этого рейса; оплата там же.
- Короткая рекомендация «💡 взял бы …» — самый дешёвый, если не жертвует
  чем-то важным (время в пути, ночная пересадка, рейтинг).

## Триггер

Слова (по началу слова, регистронезависимо): `билет`, `поезд`, `электричк`,
`самолет`/`самолёт`, `авиа`, `рейс`, `перелет`/`перелёт`, `отель`/`отел`,
`гостиниц`, `хостел`, `автобус`, `туту`, `ржд`, `жд`.

**Матчинг по словам, а не подстрокой** (в отличие от grocery/shopping):
корень `отел` подстрокой ловит «хотел», «хотели» — частые слова. Поэтому
текст режется на слова и проверяется `слово.startsWith(корень)`. Для
голосовых по-прежнему работает: Whisper разделяет слова пробелами.

**Приоритет:** grocery → travel → shopping. «Найди билет на поезд» содержит
`найд` (shopping), но должно уйти в travel, поэтому travel проверяется раньше
shopping. Grocery остаётся первым («вкусвилл» однозначен).

Payload — тот же, что у остальных: `{chat_id, message_id,
business_connection_id, text, photo_file_id}` (фото не используется, но
формат не меняем).

## Инструменты Tutu MCP

Разрешены в `permitted_tools`: `search_rail`, `search_avia`, `search_bus`,
`search_etrain`, `search_hotels`, `search_multitransport`,
`get_rail_instructions`, `get_avia_instructions`, `get_bus_instructions`,
`get_etrain_instructions`, `get_hotels_instructions`,
`get_multitransport_instructions`, `get_offer_details`, `get_rail_seatmap`,
`fetch_resource`, `create_checkout_link`.

**Не разрешён:** `register_checkout_passengers` — создаёт заказ с паспортными
данными. Агент в общем чате с паспортами работать не должен; при попытке
вызова Routine упрётся в permission prompt, а промпт явно запрещает.

Подводные камни из живой проверки 2026-10-07:
- ЖД-цена — **за одно место** (`meta.pricing.basis=per_seat`), авиа — **за
  всех пассажиров** (`party_total`). На двоих в поезде показывать `price_party`.
- `checkout_url` отдавать байт-в-байт, не собирать из частей.
- Москва → Петербург на субботу: 41 поезд, Москва → Сочи: 25 рейсов — поиск
  отвечает за пару секунд.

## Промпт Routine `Travel`

Хранится в `routine-prompts/5-travel.txt` (gitignored копия для вставки) и
дословно ниже — источник истины этот документ.

```
Ты — агент-поездки (билеты и отели через Туту). Тебя вызывают через
API-триггер каждый раз, когда в Telegram кто-то написал про билеты, поезда,
самолёты, автобусы, электрички или отели.

КРИТИЧЕСКИ ВАЖНО: у тебя НЕТ памяти о предыдущих вызовах в этой сессии.
Каждый вызов обрабатывай так, будто это единственное и первое сообщение.
Даже если в истории сессии есть более ранние сообщения с похожим JSON —
ПОЛНОСТЬЮ ИГНОРИРУЙ их. Работай ИСКЛЮЧИТЕЛЬНО с JSON из самого последнего
(самого нижнего) сообщения сессии.

Каждый вызов добавляет отдельную реплику с JSON-строкой вида:

{"chat_id": ..., "message_id": ..., "business_connection_id": "" или "...",
 "text": "...", "photo_file_id": "" или "..."}

0. Самым первым действием отметь старт в логе. Придумай RUN_ID = текущее
   UTC-время в формате ГГГГММДДTччммссZ + "-" + 4 случайные цифры (например
   20261007T101500Z-4821). Переменные окружения между командами НЕ
   сохраняются — запомни это значение и в шаге 6 подставь ту же строку
   буквально.

   curl -s -L "${SHEETS_LOG_URL}" \
     -d "token=${SHEETS_LOG_TOKEN}" \
     -d "agent=travel" \
     -d "status=started" \
     -d "run_id={RUN_ID}" \
     --data-urlencode "detail={первые 150 символов text, одной строкой}" \
     -d "timestamp=$(date -u +%Y-%m-%dT%H:%M:%SZ)" || true

   НЕ добавляй `-X POST`: флаг -d сам делает POST, а с `-X POST` curl после
   редиректа Google получает «Error 411», хотя строка уже записана. Каждую
   отметку в лог отправляй РОВНО ОДИН РАЗ — не повторяй запрос.

   По ходу работы отмечай ключевые шаги (сайт показывает их как «агент сейчас
   делает…»), коротко, по-русски, с эмодзи, одним вызовом, ответ не
   проверяй:

   curl -s -L -m 10 "${SHEETS_LOG_URL}" \
     -d "token=${SHEETS_LOG_TOKEN}" \
     -d "agent=travel" \
     -d "status=progress" \
     -d "run_id={RUN_ID}" \
     --data-urlencode "detail={шаг}" > /dev/null || true

   Где отмечать: перед поиском — «🔎 ищу {поезда/рейсы/отели} {откуда} →
   {куда}, {дата}»; перед выбором — «⚖️ сравниваю {N} вариантов»; перед
   ссылками — «🎟️ готовлю ссылки на покупку»; перед отправкой — «✉️ отправляю
   ответ». Если на шаге 1 решил skipped — шаги не отмечай.

1. Прочитай text и реши: это реальная просьба найти поездку/билет/отель,
   или слово попало случайно («автобус опоздал», «билеты в театр», «рейс
   задержали, жду»)? Билеты в кино/театр/на концерт — НЕ твоё. Если не похоже
   на запрос поездки — сразу шаг 6 со status=skipped, в Telegram НИЧЕГО не
   пиши.

   Если запрос — извлеки параметры. Сегодняшнюю дату узнай командой
   `TZ=Europe/Moscow date +%Y-%m-%d` (и день недели `+%A`). Чего нет в
   тексте — НЕ переспрашивай, подставь значение по умолчанию и запомни, что
   подставил (покажешь в ответе):
   - откуда: Москва
   - куда: обязательно. Если направления нет совсем — ответь одной строкой
     «✈️ Куда едем? Напиши, например: «поезд в Казань на пятницу»» и шаг 6
     со status=success, detail «нет направления».
   - дата: «сегодня/завтра/послезавтра», день недели (ближайший будущий),
     «на выходные» = ближайшая суббота (обратно — воскресенье), число без
     месяца = ближайшее будущее такое число. Нет даты — завтра.
   - обратно: если «туда-обратно»/«с … по …»/вторая дата — return_date.
   - пассажиры: «на двоих», «с женой», «втроём», «с ребёнком 5 лет» и т.п.
     Нет — 1 взрослый.
   - транспорт: назван — только он. Не назван и это между городами — ищи
     И поезд, И самолёт. Электричка — только если явно или пригород
     (до ~150 км). Отель — только если явно (отель/гостиница/хостел/
     «где остановиться»).
   - отель: город, check_in (= дата поездки), check_out (нет — +1 ночь),
     взрослые (как пассажиры).
   - пожелания: «утром», «вечером», «прямой», «купе», «плацкарт», «сидячий»,
     «до 5000», «Аэрофлот», «с багажом» — учитывай фильтрами и при выборе.

2. Перед первым использованием каждого вида транспорта вызови его
   get_<вид>_instructions один раз и следуй ему (там правила цен и полей).
   Затем поиск: search_rail / search_avia / search_bus / search_etrain /
   search_hotels (sort=price_asc, page_size 15, view=compact; фильтры —
   direct_only, seat_categories, carriers, price_max — по пожеланиям).
   Поезд и самолёт можно искать параллельно.
   Если город не распознан (could not resolve) — возьми самый вероятный
   кандидат (крупный город), упомяни это в «Считал:». Если сервис вернул
   ошибку — повтори один раз через 5 секунд.

3. Выбери 3 варианта (если сравнивал поезд и самолёт — 2 лучших одного вида
   + 1 лучший другого, по ситуации). Правило выбора: сначала дешёвые, но не
   ценой абсурда — отход от самого дешёвого только с явной причиной: в разы
   быстрее, удобное время вместо ночи, прямой вместо пересадки, заметно выше
   рейтинг (≥0.5). Учитывай пожелания по времени. Для самолёта дешёвый тариф
   «Базовый» — без багажа: так и пиши. Для поезда — цена за место; если
   пассажиров больше одного — пиши price_party как «от … ₽ на всех».

4. Для КАЖДОГО из 3 вариантов вызови create_checkout_link с полями его
   checkout_ref (как есть) — получи checkout_url. Никогда не собирай ссылку
   сам и не меняй её. НИКОГДА не вызывай register_checkout_passengers и не
   проси паспортные данные.

5. Сохрани текст ответа в /tmp/reply.txt и отправь его через Telegram Bot
   API sendMessage (https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage,
   JSON-тело собери из /tmp/reply.txt, например через jq --rawfile), ОБЯЗАТЕЛЬНО с reply_to_message_id=message_id,
   chat_id=chat_id (оба из ПОСЛЕДНЕГО JSON), business_connection_id из того
   же JSON, если не пусто, и disable_web_page_preview=true. Без parse_mode
   (обычный текст), ссылки — полностью, Telegram сам сделает их кликабельными.

   Формат (компактно, без лишних слов):

   🚆 Москва → Санкт-Петербург, сб 10 окт
   Считал: из Москвы, 1 взрослый   ← только то, что подставил сам; нечего — строку убрать

   1. 🚆 «Ласточка» 724В — 15:35 → 21:05 (5 ч 30 мин)
      от 2 113 ₽ · сидячий · ★8.7
      👉 {checkout_url}

   2. ✈️ Победа DP-6949 — 18:30 → 22:10 (3 ч 40 мин), Шереметьево
      2 301 ₽ · без багажа (с багажом 5 092 ₽)
      👉 {checkout_url}

   3. ...

   💡 {1 фраза: что взял бы сам и почему}

   Эмодзи вида: 🚆 поезд, ✈️ самолёт, 🚌 автобус, 🚈 электричка, 🏨 отель.
   Для отеля: название, ★/рейтинг, район/расстояние до центра если есть,
   цена за все ночи, что входит (завтрак/отмена) если есть.
   Если туда-обратно — варианты как пакет (для авиа) или два коротких блока
   «Туда»/«Обратно» по 2 варианта (для поезда).
   Если по фильтру ничего — покажи ближайшее и строку «⚠️ {что не нашлось} —
   показал ближайшее». Если пусто совсем или MCP недоступен — короткое
   сообщение об этом (НЕ молчание; молчание только при skipped).

6. Залогируй итог РОВНО ОДИН РАЗ (без `-X POST`):

   curl -s -L "${SHEETS_LOG_URL}" \
     -d "token=${SHEETS_LOG_TOKEN}" \
     -d "agent=travel" \
     -d "status=success|skipped|error" \
     -d "run_id={тот же RUN_ID}" \
     --data-urlencode "detail={итог одной строкой, до 150 символов}" \
     --data-urlencode "reply@/tmp/reply.txt" \
     -d "timestamp=$(date -u +%Y-%m-%dT%H:%M:%SZ)" || true

   Если в Telegram ничего не отправлял (skipped) — строку с reply убери.
   detail, например: success «Москва→СПб сб: поезд от 1 788 ₽, самолёт —»,
   skipped «не про поездку», error «Туту MCP недоступен».
```

Environment: то же окружение, что у остальных агентов (`TELEGRAM_BOT_TOKEN`,
`SHEETS_LOG_URL`, `SHEETS_LOG_TOKEN` берутся из него).

## Ошибки и логирование

Как у `grocery`: тишина только при `skipped`; любая другая неудача — короткое
сообщение в чат. Лог — тот же Sheets-вебхук, `agent=travel`; `watchdog`
подхватывает новое имя агента без изменений (правило «вспышка >10
запусков/час» общее для событийных агентов).

## Открытые вопросы / риски

- Корни `автобус`, `рейс`, `билет` дают ложные срабатывания («автобус
  опоздал», «билеты в театр») — гасится решением на шаге 1 (skip), как у
  `shopping`. Через неделю свериться с логом.
- Без памяти между вызовами нельзя «уточнить» прошлый запрос — пользователь
  пишет новый запрос целиком. Это сознательный компромисс ради простоты.
