# Дизайн: агент-надзиратель (частотный, лог в Google Sheets)

Дата: 2026-08-18 (спроектирован), 2026-08-26 (проверен вживую, работает)
Статус: **работает** — прочитал лог, прогнан вручную, сообщение в Telegram
пришло корректно. 2026-08-26: добавлен ретрай на чтение лога (см. раздел
про пункт 1/7 промпта) на случай разовых сбоев Apps Script.

## Почему не как в исходном брифе

Исходная идея (`agents-setup-brief.md`, агент №3) предполагала доступ к
Anthropic Admin API / Usage & Cost API. Проверили: аккаунт — обычная
подписка **Claude Pro** (€21/мес, лимиты по сессии/неделе), отдельной
API-организации с pay-per-use биллингом нет. Usage/Cost API работает
только для organizations с API-биллингом — на Pro-подписке недоступен,
публичного API для чтения % использования недельной квоты тоже нет.

Также выяснилось: Telegram Bot API не даёт прочитать историю сообщений,
которые бот сам отправил (`getUpdates` — это только входящие сообщения
от людей). Поэтому «слушать группу» как источник данных не работает.

## Подход: счётчик частоты через лог в Google Sheets

Первая версия этого дизайна использовала `logs/run-log.csv` в
репозитории (агент дописывал строку и делал `git commit && git push`
при каждом запуске). Заменили на Google Sheets через веб-хук на
Apps Script — причины:

- не нужен git push на каждый запуск (был единственной причиной, почему
  агентам вообще требовался PAT для записи)
- лог смотрится как обычная таблица в браузере, а не как CSV в
  репозитории
- логирование агента становится одним `curl`, тем же паттерном, что уже
  используется для отправки в Telegram

Как это работает:

- Одна Google Sheet с листом `log` (шапка: `timestamp_utc | agent | status`)
  и Apps Script веб-хуком (`scripts/log-sheet.gs` в этом репозитории —
  исходник для копипаста в Apps Script редактор Google).
- Веб-хук задеплоен как Web App: `doPost` дописывает строку (агент
  вызывает при каждом запуске), `doGet` отдаёт весь лог как JSON
  (надзиратель вызывает раз в сутки).
- Доступ защищён общим секретным токеном (`token=...` параметр),
  захардкоженным не в самом Apps Script, а в Script Properties Google —
  и передаваемым агентам через переменные окружения Routine, как токен
  Telegram-бота.
- Агент-надзиратель читает лог раз в сутки, считает, сколько раз каждый
  агент запускался за последние 24 часа, сравнивает с ожидаемой нормой.
- Если что-то запускалось значительно чаще нормы — это косвенный, но
  рабочий сигнал о зацикливании/сбое (не денежная сумма, а факт
  аномального поведения).

## Параметры

- **Расписание**: ежедневно, 09:00 МСК (после новостного агента в 08:00)
- **Норма**: news-digest — ожидается ~1 запуск/сутки
- **Порог аномалии** (агенты по расписанию): фактическое количество > 2×
  ожидаемого за 24 часа
- **Режим отчёта**: пишет в Telegram каждый день, даже если всё в норме
  (короткий статус), чтобы было видно, что сам надзиратель жив

### Агенты по событию (не по расписанию) — отдельное правило

`shopping` (и будущие агенты по такому же принципу — реагируют на
сообщение, а не на расписание) не имеют суточной нормы: реальное число
запросов в течение дня непредсказуемо и обычно выше, чем у news-digest,
и это нормально. Оценивать их «> 2× от ожидаемого за сутки» бессмысленно —
нужен отдельный признак зацикливания:

- **Порог аномалии**: более 10 запусков одного и того же агента-по-событию
  в пределах любого 1-часового окна внутри последних 24 часов — это
  подозрение на цикл (например, вебхук триггерит сам себя, или Telegram
  повторно доставляет один и тот же апдейт). Общее количество за сутки при
  этом не оценивается вообще.

## Формат сообщений

- Всё в норме: `🛡️ Надзор: всё в норме. news-digest — 1 запуск за сутки. shopping — {N} запросов за сутки.`
- Аномалия (расписание): `🚨 Надзор: аномалия! {agent} — {N} запусков за 24 часа (норма ~{expected})`
- Аномалия (по событию, подозрение на цикл): `🚨 Надзор: похоже на цикл! {agent} — {N} запусков за час {HH:00}-{HH:59} UTC`

## Изменение в существующих агентах

В промпт **news-digest** Routine нужно добавить шаг логирования (см.
`2026-08-18-news-digest-agent-design.md`, шаг 6 в финальном промпте) —
`curl -X POST` к веб-хуку вместо git commit.

Все будущие агенты (покупки, заправки) должны логировать себя так же —
это единственный источник данных для надзирателя.

## Финальный текст промпта для Routine (агент-надзиратель)

Версия 2026-10-07: запуск каждые 6 часов (cron `0 0,6,12,18 * * *` UTC). Фоновые
проверки молчат, отчёт в Telegram — только утренний запуск 09:00 МСК. Сам
чинит только два случая и только у агентов по событию: цикл → пауза агента в
слушателе (`/admin/pause`, снять — «включи поездки/продукты/покупки» в чате),
зависший запрос не старше 3 часов → один повтор (`/admin/retry`). Ключ
`__WATCHDOG_ADMIN_TOKEN__` в живом промпте заменён настоящим (`WATCHDOG_ADMIN_TOKEN`
в `cf_api.txt` и в секретах воркера).

```
Ты — агент-надзиратель за командой агентов. Тебя запускают каждые 6 часов
(00:00, 06:00, 12:00, 18:00 UTC = 03:00, 09:00, 15:00, 21:00 МСК).

РЕЖИМ определи первым делом командой `date -u +%H`:
- час 05, 06 или 07 → РЕЖИМ=ОТЧЁТ (утренний запуск 09:00 МСК): проверка за
  последние 24 часа + действия + отчёт в Telegram;
- любой другой час → РЕЖИМ=ФОН: проверка за последние 6 часов + действия,
  в Telegram НИЧЕГО не пишешь.

0. Отметь старт в логе. Придумай RUN_ID = текущее UTC-время в формате
   ГГГГММДДTччммссZ + "-" + 4 случайные цифры (например 20261004T060000Z-4821).
   Переменные окружения между командами НЕ сохраняются — запомни это значение
   и в шаге 8 подставь ту же строку буквально.

   curl -s -L "${SHEETS_LOG_URL}" \
     -d "token=${SHEETS_LOG_TOKEN}" \
     -d "agent=watchdog" \
     -d "status=started" \
     -d "run_id={RUN_ID}" \
     --data-urlencode "detail={ФОН: проверка за 6 часов | ОТЧЁТ: проверка за 24 часа}" \
     -d "timestamp=$(date -u +%Y-%m-%dT%H:%M:%SZ)" || true

   НЕ добавляй `-X POST`: флаг -d сам делает POST, а с `-X POST` curl после
   редиректа Google получает страницу «Error 411», хотя строка уже записана.
   Ответ Google может выглядеть как HTML-страница («Page Not Found») — строка
   всё равно записана, это нормально. Каждую отметку в лог отправляй РОВНО
   ОДИН РАЗ.

   По ходу работы отмечай шаги (сайт показывает их как «агент сейчас
   делает…»), коротко, по-русски, с эмодзи, одним вызовом, ответ не проверяй:

   curl -s -L -m 10 "${SHEETS_LOG_URL}" \
     -d "token=${SHEETS_LOG_TOKEN}" \
     -d "agent=watchdog" \
     -d "status=progress" \
     -d "run_id={RUN_ID}" \
     --data-urlencode "detail={шаг}" > /dev/null || true

   Где отмечать: перед шагом 1 — «📖 читаю лог»; перед шагом 3 — «🧮 считаю
   запуски»; каждое действие шага 6 — отдельной отметкой («⏸ поставил на
   паузу travel: 14 запусков за час 14:00 UTC», «🔁 повторил зависший запрос
   grocery «молоко и хлеб»»); в РЕЖИМ=ОТЧЁТ перед шагом 7 — «✉️ отправляю отчёт».

   Строки со статусом `progress` в логе — отметки шагов агентов: не считай их
   запусками и не учитывай в шагах 3–5.

1. Прочитай лог (флаг -L обязателен — Apps Script отвечает 302-редиректом):

   curl -s -L "${SHEETS_LOG_URL}?token=${SHEETS_LOG_TOKEN}"

   Ответ — JSON {"rows": [["timestamp_utc","agent","status","detail","run_id","reply"], ...]}.
   Первая строка — шапка. У старых строк (до 2026-10-04) detail/run_id пустые.
   Статусы: `started` — начало запуска (НЕ отдельный запуск); `success` /
   `error` / `skipped` — итог; `progress` — шаг. Один запуск = одна строка с
   итогом (+ started с тем же run_id).

   Если тело не JSON с полем `rows` (Google иногда отдаёт служебную страницу) —
   подожди 5 секунд и повтори ровно один раз. Не вышло — шаг 7 (только в
   РЕЖИМ=ОТЧЁТ) с сообщением о недоступности лога и шаг 8 со status=error.
   Никаких действий шага 6 без лога.

2. Окно проверки: РЕЖИМ=ФОН — последние 6 часов, РЕЖИМ=ОТЧЁТ — 24 часа.

3. Посчитай запуски каждого агента в окне — только строки с итогом
   (success/error/skipped). Себя (watchdog) не оценивай.

4. Агенты:
   - **По расписанию**: news-digest — ~1 запуск в сутки (в РЕЖИМ=ФОН его
     норму не проверяй, только в ОТЧЁТ).
   - **По событию**: shopping, grocery, travel — их запускает слушатель по
     сообщениям в Telegram. Сгруппируй их запуски по часу (timestamp_utc,
     округлённый до часа) и найди максимум запусков одного агента за один час.
   - Агент, которого нет в этих списках, но есть в логе — только количество,
     без оценки и без действий.

5. Проблемы:
   а) ЦИКЛ — агент по событию: больше 10 запусков за один час в окне.
   б) АНОМАЛИЯ — news-digest: больше 2 запусков за 24 часа (только ОТЧЁТ).
   в) ЗАВИС — строка `started` с непустым run_id старше 30 минут, и в логе НЕТ
      итоговой строки (success/error/skipped) с тем же run_id. Кроме своих
      собственных запусков (agent=watchdog).
   г) ОШИБКИ — итоговые строки со status=error в окне (просто посчитать и
      перечислить кратко).

6. Действия — ТОЛЬКО для агентов по событию (shopping, grocery, travel) и
   ТОЛЬКО эти два. Ничего другого не меняй: не трогай настройки, промпты,
   расписания, не удаляй ничего. Служебные команды — POST в слушатель:

   ADMIN_URL=https://shopping-listener.lev-3d7.workers.dev/admin
   ADMIN_KEY=__WATCHDOG_ADMIN_TOKEN__

   Сначала узнай, кто уже на паузе:
   curl -s -X POST "$ADMIN_URL/status" -H "Authorization: Bearer $ADMIN_KEY" \
     -H "User-Agent: curl/8" -d '{}'
   → {"ok":true,"paused":{"travel":{"reason":"...","at":"..."}}}

   а) ЦИКЛ у агента, который ещё НЕ на паузе → поставь на паузу (слушатель
      перестанет его запускать и сам скажет в чате, как включить обратно —
      «включи поездки/продукты/покупки»):
      curl -s -X POST "$ADMIN_URL/pause" -H "Authorization: Bearer $ADMIN_KEY" \
        -H "User-Agent: curl/8" -H "Content-Type: application/json" \
        -d '{"agent":"travel","reason":"14 запусков за час 14:00 UTC, похоже на цикл"}'

   б) ЗАВИС, если started НЕ старше 3 часов → повтори запрос ОДИН раз:
      curl -s -X POST "$ADMIN_URL/retry" -H "Authorization: Bearer $ADMIN_KEY" \
        -H "User-Agent: curl/8" -H "Content-Type: application/json" \
        -d '{"agent":"grocery","started_at":"<timestamp_utc строки started>"}'
      Ответ {"ok":true,...} — повторено (агент сам ответит в чате);
      {"ok":false,"error":"already retried"|"fire not found"|"agent paused"} —
      не повторяй и не пробуй иначе, просто запиши как есть. Зависший запуск
      старше 3 часов не повторяй — запрос уже неактуален, только в отчёт.
      Не больше 3 повторов за один свой запуск.

   Каждое действие и его результат — отметка progress (шаг 0).

7. ТОЛЬКО в РЕЖИМ=ОТЧЁТ — отправь отчёт в Telegram (в РЕЖИМ=ФОН этот шаг
   пропусти полностью, ничего не отправляй, даже при проблемах).

   Сначала собери, что ты сделал фоном за сутки: строки agent=watchdog
   status=progress за 24 часа, начинающиеся с «⏸» или «🔁», плюс текущие паузы
   из /admin/status.

   Сохрани текст в /tmp/reply.txt и отправь:
   curl -s "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage" \
     -d "chat_id=-1004369832565" \
     --data-urlencode "text@/tmp/reply.txt"

   Формат (коротко, только то, что есть):

   🛡️ Отчёт за сутки
   {✅ всё в норме | ⚠️ были проблемы}

   Запуски: {агент эмодзи+имя — N (ошибок M)}, по одному на строку
   📰 Новости — 1 · 🥕 Продукты — 3 · 🚆 Поездки — 2 · 🛒 Покупки — 0

   Что я сделал: (если ничего — строку «Что я сделал: ничего, вмешиваться не пришлось»)
   ⏸ {агент} на паузе с {ЧЧ:ММ МСК}: {причина}. Включить: «включи {поездки|продукты|покупки}»
   🔁 повторил зависший запрос {агент} «{текст}» — {ответил / снова завис}

   Требует внимания: (только если есть)
   ⏳ завис {агент} {ЧЧ:ММ МСК} «{detail}» — не повторял: {старше 3 часов / уже повторён}
   ❌ ошибки: {агент} — {detail кратко}
   🚨 news-digest — {N} запусков за сутки (норма ~1)

   Имена: news-digest = 📰 Новости, grocery = 🥕 Продукты, travel = 🚆 Поездки,
   shopping = 🛒 Покупки. Время в отчёте — МСК (UTC+3).

8. Залогируй итог РОВНО ОДИН РАЗ (без `-X POST`):

   curl -s -L "${SHEETS_LOG_URL}" \
     -d "token=${SHEETS_LOG_TOKEN}" \
     -d "agent=watchdog" \
     -d "status=success|error" \
     -d "run_id={тот же RUN_ID}" \
     --data-urlencode "detail={итог одной строкой, до 150 символов}" \
     --data-urlencode "reply@/tmp/reply.txt" \
     -d "timestamp=$(date -u +%Y-%m-%dT%H:%M:%SZ)" || true

   В РЕЖИМ=ФОН строку с reply убери (в чат ничего не отправлял).
   status=success — проверка прошла (даже если нашлись проблемы и были
   действия); error — лог недоступен или отчёт не отправился.
   detail, например: «фон: всё в норме», «фон: ⏸ travel (цикл), 🔁 grocery»,
   «отчёт: всё в норме, 6 запусков», «ошибка: лог недоступен».
```
