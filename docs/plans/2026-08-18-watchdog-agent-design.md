# Дизайн: агент-надзиратель (частотный, без Usage/Cost API)

Дата: 2026-08-18
Статус: готов к настройке в UI (claude.ai/code/routines)

## Почему не как в исходном брифе

Исходная идея (`agents-setup-brief.md`, агент №3) предполагала доступ к
Anthropic Admin API / Usage & Cost API. Проверили: аккаунт — обычная
подписка **Claude Pro** (€21/мес, лимиты по сессии/неделе), отдельной
API-организации с pay-per-use биллингом нет. Usage/Cost API работает
только для organizations с API-биллингом — на Pro-подписке недоступен,
публичного API для чтения % использования недельной квоты тоже нет.

Также выяснилось: Telegram Bot API не даёт прочитать историю сообщений,
которые бот сам отправил (`getUpdates` — это только входящие сообщения
от людей). Поэтому «слушать группу» как источник данных не работает.

## Новый подход: счётчик частоты через лог в репозитории

- Каждый агент при каждом запуске дописывает строку в
  `logs/run-log.csv` (формат: `timestamp_utc,agent,status`) и коммитит
  это вместе с остальными изменениями в репозитории.
- Агент-надзиратель читает этот файл раз в сутки, считает, сколько раз
  каждый агент запускался за последние 24 часа, сравнивает с ожидаемой
  нормой.
- Если что-то запускалось значительно чаще нормы — это косвенный, но
  рабочий сигнал о зацикливании/сбое (не денежная сумма, а факт
  аномального поведения).

## Параметры

- **Расписание**: ежедневно, 09:00 МСК (после новостного агента в 08:00)
- **Норма**: news-digest — ожидается ~1 запуск/сутки
- **Порог аномалии**: фактическое количество > 2× ожидаемого за 24 часа
- **Режим отчёта**: пишет в Telegram каждый день, даже если всё в норме
  (короткий статус), чтобы было видно, что сам надзиратель жив

## Формат сообщений

- Всё в норме: `🛡️ Надзор: всё в норме. news-digest — 1 запуск за сутки.`
- Аномалия: `🚨 Надзор: аномалия! {agent} — {N} запусков за 24 часа (норма ~{expected})`

## Изменение в существующих агентах

В промпт **news-digest** Routine нужно добавить шаг логирования (перед
или после отправки в Telegram — не влияет на порядок):

```
6. Допиши строку в файл logs/run-log.csv в текущем репозитории в формате:
   {текущая дата и время в ISO 8601, UTC},news-digest,{success или error}
   Затем закоммить и запушь изменение (git add, git commit, git push) —
   если это не первый коммит в сессии, используй короткое сообщение
   коммита вида "log: news-digest run".
```

Все будущие агенты (покупки, заправки) должны логировать себя так же —
это единственный источник данных для надзирателя.

## Финальный текст промпта для Routine (агент-надзиратель)

```
Ты — агент-надзиратель за расходами команды агентов. Раз в день:

1. Прочитай файл logs/run-log.csv из текущего репозитория.

2. Отфильтруй строки за последние 24 часа (по колонке timestamp_utc).

3. Посчитай количество запусков каждого агента (колонка agent) за этот
   период.

4. Сравни с ожидаемой нормой:
   - news-digest: ожидается ~1 запуск в сутки
   - (для агентов, которых нет в этом списке, но они есть в логе —
     просто укажи их количество без оценки нормы, не считай ошибкой)

5. Если фактическое количество запусков какого-либо агента более чем в
   2 раза превышает ожидаемую норму — это аномалия.

6. Отправь сообщение в Telegram через Bot API:

   curl -s "https://api.telegram.org/bot8651950364:AAHgf7eAY76yGLBmSkodP-cHVrKeyR2dYkU/sendMessage" \
     -d "chat_id=-1004369832565" \
     --data-urlencode "text@-" <<< "$MESSAGE"

   Если аномалий нет:
   🛡️ Надзор: всё в норме. {список агентов и их количество запусков за сутки}

   Если есть аномалия:
   🚨 Надзор: аномалия! {agent} — {N} запусков за 24 часа (норма ~{expected})
   (можно упомянуть и остальных агентов без аномалий кратко)

7. Если файл logs/run-log.csv не найден или пуст — напиши в Telegram
   короткое сообщение об этом (возможно, ни один агент ещё не запускался
   с момента внедрения логирования), не считай это ошибкой первого рода.
```

## Дальнейшие шаги

1. Создать Routine с этим промптом, репозиторий `Lereactor/agents-setup`,
   расписание 09:00 МСК = 06:00 UTC, Network access = Full, то же
   cloud-окружение, что и у news-digest
2. Обновить промпт news-digest Routine — добавить шаг логирования (текст
   выше)
3. Прогнать news-digest вручную (Run now), убедиться что появилась
   строка в logs/run-log.csv в репозитории
4. Прогнать надзирателя вручную, проверить сообщение в Telegram
