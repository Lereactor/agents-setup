# Дизайн: агент-надзиратель (частотный, лог в Google Sheets)

Дата: 2026-08-18
Статус: готов к настройке в UI (claude.ai/code/routines) + деплою Apps Script

## Почему не как в исходном брифе

Исходная идея (`agents-setup-brief.md`, агент №3) предполагала доступ к
Anthropic Admin API / Usage & Cost API. Проверили: аккаунт — обычная
подписка **Claude Pro** (€21/мес, лимиты по сессии/неделе), отдельной
API-организации с pay-per-use биллингом нет. Usage/Cost API работает
только для organizations с API-биллингом — на Pro-подписке недоступен,
публичного API для чтения % использования недельной квоты тоже нет.

Также выяснилось: Telegram Bot API не даёт прочитать историю сообщений,
которые бот сам отправил (`getUpdates` — это только входящие сообщения
от людей). Поэтому «слушать группу» как источник данных не работает.

## Подход: счётчик частоты через лог в Google Sheets

Первая версия этого дизайна использовала `logs/run-log.csv` в
репозитории (агент дописывал строку и делал `git commit && git push`
при каждом запуске). Заменили на Google Sheets через веб-хук на
Apps Script — причины:

- не нужен git push на каждый запуск (был единственной причиной, почему
  агентам вообще требовался PAT для записи)
- лог смотрится как обычная таблица в браузере, а не как CSV в
  репозитории
- логирование агента становится одним `curl`, тем же паттерном, что уже
  используется для отправки в Telegram

Как это работает:

- Одна Google Sheet с листом `log` (шапка: `timestamp_utc | agent | status`)
  и Apps Script веб-хуком (`scripts/log-sheet.gs` в этом репозитории —
  исходник для копипаста в Apps Script редактор Google).
- Веб-хук задеплоен как Web App: `doPost` дописывает строку (агент
  вызывает при каждом запуске), `doGet` отдаёт весь лог как JSON
  (надзиратель вызывает раз в сутки).
- Доступ защищён общим секретным токеном (`token=...` параметр),
  захардкоженным не в самом Apps Script, а в Script Properties Google —
  и передаваемым агентам через переменные окружения Routine, как токен
  Telegram-бота.
- Агент-надзиратель читает лог раз в сутки, считает, сколько раз каждый
  агент запускался за последние 24 часа, сравнивает с ожидаемой нормой.
- Если что-то запускалось значительно чаще нормы — это косвенный, но
  рабочий сигнал о зацикливании/сбое (не денежная сумма, а факт
  аномального поведения).

## Параметры

- **Расписание**: ежедневно, 09:00 МСК (после новостного агента в 08:00)
- **Норма**: news-digest — ожидается ~1 запуск/сутки
- **Порог аномалии** (агенты по расписанию): фактическое количество > 2×
  ожидаемого за 24 часа
- **Режим отчёта**: пишет в Telegram каждый день, даже если всё в норме
  (короткий статус), чтобы было видно, что сам надзиратель жив

### Агенты по событию (не по расписанию) — отдельное правило

`shopping` (и будущие агенты по такому же принципу — реагируют на
сообщение, а не на расписание) не имеют суточной нормы: реальное число
запросов в течение дня непредсказуемо и обычно выше, чем у news-digest,
и это нормально. Оценивать их «> 2× от ожидаемого за сутки» бессмысленно —
нужен отдельный признак зацикливания:

- **Порог аномалии**: более 10 запусков одного и того же агента-по-событию
  в пределах любого 1-часового окна внутри последних 24 часов — это
  подозрение на цикл (например, вебхук триггерит сам себя, или Telegram
  повторно доставляет один и тот же апдейт). Общее количество за сутки при
  этом не оценивается вообще.

## Формат сообщений

- Всё в норме: `🛡️ Надзор: всё в норме. news-digest — 1 запуск за сутки. shopping — {N} запросов за сутки.`
- Аномалия (расписание): `🚨 Надзор: аномалия! {agent} — {N} запусков за 24 часа (норма ~{expected})`
- Аномалия (по событию, подозрение на цикл): `🚨 Надзор: похоже на цикл! {agent} — {N} запусков за час {HH:00}-{HH:59} UTC`

## Изменение в существующих агентах

В промпт **news-digest** Routine нужно добавить шаг логирования (см.
`2026-08-18-news-digest-agent-design.md`, шаг 6 в финальном промпте) —
`curl -X POST` к веб-хуку вместо git commit.

Все будущие агенты (покупки, заправки) должны логировать себя так же —
это единственный источник данных для надзирателя.

## Финальный текст промпта для Routine (агент-надзиратель)

```
Ты — агент-надзиратель за расходами команды агентов. Раз в день:

1. Прочитай лог через GET-запрос (флаг -L обязателен — Apps Script
   всегда отвечает 302-редиректом на скрытый URL с реальными данными,
   без -L тело ответа будет пустым):

   curl -s -L "${SHEETS_LOG_URL}?token=${SHEETS_LOG_TOKEN}"

   Ответ — JSON вида {"rows": [["timestamp_utc","agent","status"], [...], ...]}
   Первая строка — шапка, пропусти её.

2. Отфильтруй строки за последние 24 часа (по колонке timestamp_utc).

3. Посчитай количество запусков каждого агента (колонка agent) за этот
   период.

4. Раздели агентов на две категории:
   - **По расписанию** (сейчас: news-digest — ожидается ~1 запуск в
     сутки). Сравни фактическое количество за 24 часа с нормой.
   - **По событию** (сейчас: shopping). У них нет суточной нормы —
     вместо этого сгруппируй их запуски по часу (`timestamp_utc`,
     округлённый до часа) и найди максимум запусков одного агента в
     пределах одного часа за последние 24 часа.
   - (агент, которого нет ни в одном из этих двух списков, но есть в
     логе — просто укажи количество за сутки без оценки, не считай
     ошибкой)

5. Аномалия, если:
   - агент по расписанию: фактическое количество за 24 часа более чем в
     2 раза превышает норму;
   - агент по событию: в каком-либо часовом окне за последние 24 часа
     было больше 10 запусков одного и того же агента (подозрение на
     цикл).

6. Отправь сообщение в Telegram через Bot API:

   curl -s "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage" \
     -d "chat_id=-1004369832565" \
     --data-urlencode "text@-" <<< "$MESSAGE"

   Если аномалий нет:
   🛡️ Надзор: всё в норме. {агенты по расписанию с количеством за сутки}. {агенты по событию с количеством за сутки, без оценки}.

   Если есть аномалия по расписанию:
   🚨 Надзор: аномалия! {agent} — {N} запусков за 24 часа (норма ~{expected})

   Если есть подозрение на цикл у агента по событию:
   🚨 Надзор: похоже на цикл! {agent} — {N} запусков за час {HH:00}-{HH:59} UTC

   (можно упомянуть и остальных агентов без аномалий кратко)

7. Если запрос к SHEETS_LOG_URL вернул ошибку или пустой список строк —
   напиши в Telegram короткое сообщение об этом (возможно, ни один агент
   ещё не запускался с момента внедрения логирования), не считай это
   ошибкой первого рода.
```

## Дальнейшие шаги

1. Создать новую Google Sheet, добавить лист `log` с шапкой
   `timestamp_utc | agent | status`
2. Extensions > Apps Script в этой таблице, вставить код из
   `scripts/log-sheet.gs`
3. Project Settings > Script Properties: добавить `SECRET_TOKEN` со
   случайным значением (например `openssl rand -hex 20`)
4. Deploy > New deployment > Web app: Execute as **Me**, Who has access
   **Anyone** (доступ ограничен токеном, не Google-аккаунтом) — скопировать
   URL деплоя
5. Сохранить URL и токен локально в `sheets_api.txt` (уже добавлен в
   `.gitignore`, аналог `tg_api.txt`), формат:
   ```
   SHEETS_LOG_URL=https://script.google.com/macros/s/.../exec
   SHEETS_LOG_TOKEN=...
   ```
6. Создать Routine надзирателя с промптом выше, репозиторий
   `Lereactor/agents-setup`, расписание 09:00 МСК = 06:00 UTC, положить
   `SHEETS_LOG_URL` и `SHEETS_LOG_TOKEN` в Environment variables/Secrets
   Routine (та же логика, что и `TELEGRAM_BOT_TOKEN`)
7. Обновить промпт news-digest Routine — добавить шаг логирования (см.
   news-digest дизайн-документ, шаг 6) и те же переменные окружения
8. Прогнать news-digest вручную (Run now), проверить, что в Google Sheet
   появилась строка
9. Прогнать надзирателя вручную, проверить сообщение в Telegram
