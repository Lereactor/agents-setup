# Дизайн: AI Agent Live Visualization (отдельная демка)

Дата: 2026-08-26
Статус: в разработке
Источник спецификации: `AI_Agent_Visualization_Instruction.docx` (в корне репозитория) —
полный текст требований и «Главный промпт для AI-кодера» см. там, здесь только
решения по интеграции в этот репозиторий и отклонения от документа.

## Контекст и решение по scope

Пользователь хочет собрать проект из docx, не ломая три существующих Telegram-агента
(`news-digest`, `watchdog`, `shopping` — см. `agents-setup-brief.md`,
`docs/plans/2026-08-1{8,8,8}-*.md`, `docs/plans/2026-08-20-shopping-agent-design.md`).

Ключевое архитектурное ограничение: три существующих агента исполняются как сессии
Claude Code Routines в облаке Anthropic — Routine не отдаёт наружу пошаговые события
(«TOOL_CALL researcher→web_search» и т.п.), только финальный текстовый вывод. Docx же
описывает локальный раннер (LangGraph), который сам управляет исполнением и поэтому
может эмитить такие события в реальном времени. Это две принципиально разные модели
исполнения — подключить визуализацию из docx к текущим трём агентам без их полного
переписывания с Routines на локальный раннер невозможно.

**Решение (подтверждено пользователем):** делаем ровно то, что описано в docx —
отдельную самостоятельную демку (Supervisor/Researcher/Analyst/Reviewer/Writer,
mock-инструменты по умолчанию), никак не связанную с Telegram/Routines/Sheets. Не
трогаем ни один существующий файл в `docs/plans/`, `scripts/`, `sheets_api.txt`,
`tg_api.txt`. Новый код — в отдельной папке `ai-agent-live/` (как в разделе 9 docx).

## Отклонения от docx (по независящим от нас причинам среды)

- **LangGraph не установлен и не ставится**: `pip install` в этом окружении падает на
  SSL-проверке (похоже на перехват сертификата антивирусом/корпоративным прокси) — сеть
  для PyPI недоступна. Собрали свой `GraphRunner` (`backend/app/graph/runner.py`) на
  чистом `asyncio` за тем же интерфейсом, что и подразумевает LangGraph-раннер
  (граф узлов с зависимостями, параллельное исполнение веток) — сам docx разрешает
  «выбрать наиболее простой и надёжный вариант, совместимый с требованиями», если нужно
  архитектурное решение. Замена на настоящий LangGraph позже не потребует переписывать
  ни Event Bus, ни frontend — только реализацию `GraphRunner`.
- **Node.js не установлен на машине вообще** (ни в PATH, ни в стандартных папках) —
  фронтенд написан полностью по спецификации, но не запущен и не смок-тестирован в
  этой сессии. Инструкция по установке Node и первому запуску — в
  `docs/SETUP-GUIDE.md`, раздел про эту демку.
- Python-зависимости бэкенда (`fastapi`, `uvicorn`, `pydantic`, `pydantic-settings`,
  `python-dotenv`, `httpx`, `openai`, `websockets`) уже были установлены в системный
  Python 3.11 — ими и пользуемся, `requirements.txt` их фиксирует для переносимости на
  другую машину.

## Реализовано (2026-08-26)

Backend полностью написан и проверен вживую в этой сессии: `python -m uvicorn
app.main:app`, `POST /runs`, `GET /runs`, `GET /runs/{id}/events`, `WS /ws/{run_id}` —
полный прогон workflow (параллельная ветка Researcher/Analyst, оба tool call'а,
join в Reviewer с двумя рёбрами, Writer, RUN_COMPLETED, персистентность в
`data/traces/*.jsonl`) отработал корректно через smoke-test клиент.

Frontend полностью написан по спецификации (React + TS + Vite + React Flow,
WebSocket-клиент, Live/Replay режимы, 4 зоны интерфейса из docx §5, dark-тема из
§6) — но **не запущен и не смок-тестирован**: на машине, где вёлся этот проект, не
установлен Node.js. Требует установки Node перед первым `npm install`.

Структура проекта, команды установки/запуска, список файлов, .env-переменные,
инструкция «как добавить агента/инструмент» и полный список известных ограничений —
всё в `ai-agent-live/README.md` (не дублирую здесь, чтобы не рассинхронизировалось).
Раздел 7 `docs/SETUP-GUIDE.md` — короткая версия того же по конвенции репозитория.

**Следующий шаг** (не в этой сессии): установить Node.js, прогнать
`npm install && npm run dev`, открыть `http://127.0.0.1:5173`, нажать Start Demo,
исправить всё, что вскроется при первой реальной компиляции TypeScript/сборке.
