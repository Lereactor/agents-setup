# Дизайн: агент «marketplace» (Wildberries / Яндекс.Маркет, через self-hosted MCP)

Дата: 2026-09-21 (спроектирован)
Статус: **в разработке** — дизайн согласован, инфраструктура ещё не поднята

## Контекст

Шестой агент в системе (после `news-digest`, `watchdog`, `shopping`, `grocery`,
голосовых). Идея — по аналогии с grocery/ВкусВилл дать агенту структурированный
источник данных вместо веб-поиска, но на этот раз для Wildberries и
Яндекс.Маркета.

Разведка (см. переписку 2026-09-21) показала: у Ozon и Я.Маркета нет
официального MCP, как у ВкусВилла. Из вариантов рассмотрели:

1. `eduard256/ozon-mcp-server` — неофициальный, только stdio, требует
   локальный headless Chromium без HTTP URL — не годится (см. первую
   разведку, обсуждение сохранено в чате).
2. `Vladimir-Human/ru-marketplace-mcp` — намного зрелее (109★, 134 коммита,
   1819 тестов, MIT), поддерживает 14 источников (Wildberries, Ozon,
   Я.Маркет, Avito, Lamoda, DNS, Citilink, AliExpress, Taobao, Cian,
   Detmir, Megamarket, сравнение цен, MPStats-аналитика). Ключевое отличие
   от первого варианта — **есть HTTP-транспорт** (`MCP_TRANSPORT=http`),
   можно задеплоить как настоящий HTTP MCP-эндпоинт.

Выбрали (2) как основу, но НЕ для всех источников — только для тех, что
работают **без Chrome** (анонимные HTTP-запросы к публичным эндпоинтам,
без кредов): **Wildberries и Яндекс.Маркет**. Ozon по-прежнему требует
свой залогиненный Chrome через CDP — решили не тащить (больше
инфраструктуры, выше риск бана, надо руками поддерживать логин) и
**оставить Ozon как есть — внутри `shopping`, веб-поиском**.

**Явное решение пользователя**: `shopping` (Ozon/Я.Маркет веб-поиском) не
трогаем вообще, ни промпт, ни триггеры. Новый агент `marketplace` берёт на
себя ТОЛЬКО запросы с явным упоминанием Wildberries или Я.Маркета/Яндекса —
для остальных обращений к Я.Маркету без явного бренд-слова в тексте
по-прежнему сработает `shopping` (веб-поиском, как раньше).

Важная оговорка про легальность: `ru-marketplace-mcp` сам прямо пишет —
"marketplace terms of service generally disallow unofficial parsing",
использовать "at your discretion, for personal research, at a polite
request rate". Это неофициальный парсинг публичных страниц, не партнёрский
API — используется на свой риск, для личного некоммерческого использования.

## Архитектура

Тот же двухзвенный паттерн, что у `shopping`/`grocery`: общий Cloudflare
Worker-слушатель (без изменений в самой логике вебхука) + новый Routine
`marketplace` с API-триггером.

### Триггер и маршрутизация

Корни (регистронезависимо, substring, после `normalizeForMatching`):
`wildberries`, `вб`, `wb`, `яндекс`, `yandex`, `ямаркет` (покрывает
«я.маркет», «яндекс маркет» после нормализации не всё, `яндекс` уже ловит
любое упоминание «Яндекс.Маркет»/«яндекс маркете» и т.п.).

**Порядок проверки в `detectTarget` (от специфичного к общему)**:
grocery (`вкусвилл`/`продукт`) → **marketplace** (новое) → shopping
(`куп`/`заказ`/`найд`/`buy`/`order`/`find`). Так «купи на wildberries
кроссовки» уходит только в `marketplace`, не дублируется в `shopping`.

Формат payload идентичен остальным агентам: `{chat_id, message_id,
business_connection_id, text, photo_file_id}`.

### Self-hosted MCP-сервер

**Хостинг: Oracle Cloud Always Free** (ARM Ampere A1, честно бессрочно
бесплатный тариф) — выбран вместо Google Cloud Run ради постоянного
фиксированного IP и отсутствия cold start, что важнее для устойчивости
к антибот-фильтрам маркетплейсов, чем serverless-удобство.

Состав на VM:
1. Reserved Public IP (Oracle Free — нужно явно зарезервировать, иначе IP
   плавающий и меняется при перезапуске инстанса)
2. Docker: `ru-marketplace-mcp` с `MARKETPLACE_SOURCES=wildberries,yandex_market`
   (Chrome-источники явно не включаем — не нужны для этих двух)
3. `MCP_TRANSPORT=http`, `MCP_HTTP_HOST=0.0.0.0` (внутри контейнера),
   `MCP_HTTP_AUTH_TOKEN` / `MCP_HTTP_TENANT_ID` — случайные секреты,
   обязательны для non-loopback bind (сервер сам откажется стартовать без них)
4. **HTTPS без покупки домена**: Caddy на той же VM как reverse-proxy перед
   контейнером, домен — бесплатный wildcard DNS [sslip.io](https://sslip.io)
   (`<ip-через-дефисы>.sslip.io` резолвится в сам публичный IP) — Caddy сам
   получает и обновляет сертификат Let's Encrypt на этот адрес. Дешевле и
   проще Cloudflare Tunnel (не нужен отдельный аккаунт/домен).

**Известный риск, отдельно от ToS**: Oracle **реклеймит** ресурсы Always
Free, если инстанс простаивает (~0% CPU) 7 дней подряд. При низкой частоте
использования агента это реально может сработать без дополнительной меры.
**Митигация**: `watchdog` (уже существующий агент-надзиратель) раз в сутки
дополнительно дёргает `GET https://<host>/health` — почти нулевая
стоимость добавить, не даёт CPU уйти в полный ноль надолго.

**Не решённый эмпирически риск**: в доке `ru-marketplace-mcp` сказано, что
маркетплейсы "commonly refuse non-Russian and datacenter addresses
outright" — не проверено, заблокирует ли Wildberries/Я.Маркет запросы
именно с IP Oracle Cloud. Если да — единственный дешёвый выход residential
proxy (уже не бесплатно, см. переписку). Станет ясно только на реальном
тесте после деплоя.

## MCP-инструменты (уточнить точные имена при деплое)

Из документации проекта известно на уровне функций, не точных сигнатур:
- Яндекс.Маркет: `yandex_search(query, page, limit)` — цены обычная и с
  Яндекс+, рейтинг, продавец; `yandex_card(product_id, include_reviews)` —
  детали + отзывы
- Wildberries: 8 инструментов — поиск, карточка товара, отзывы, вопросы
  продавцу, юрлицо продавца, категории. Точные имена (`wb_search` и т.п.)
  и параметры — свериться по факту после установки (запросить у самого
  сервера список инструментов), прежде чем прописывать `permitted_tools`
  на коннекторе — неточное имя в `permitted_tools` просто не даст доступа
  к нужному инструменту без явной ошибки.

## Промпт Routine `marketplace` (черновик, доработать точными именами инструментов)

```
Ты — агент-покупки для Wildberries и Яндекс.Маркета. Тебя вызывают через
API-триггер каждый раз, когда в Telegram кто-то упомянул Wildberries/ВБ
или Яндекс.Маркет/Яндекс явным словом.

КРИТИЧЕСКИ ВАЖНО: у тебя НЕТ памяти о предыдущих вызовах в этой сессии.
Каждый вызов обрабатывай так, будто это единственное и первое сообщение.
Работай ИСКЛЮЧИТЕЛЬНО с JSON из самого последнего (самого нижнего)
сообщения сессии, полностью игнорируя более ранние.

Каждый вызов добавляет отдельную реплику с JSON-строкой вида:

{"chat_id": ..., "message_id": ..., "business_connection_id": "" или "...",
 "text": "...", "photo_file_id": "" или "..."}

1. Прочитай text целиком и реши: это реальная просьба найти/купить товар
   на Wildberries или Я.Маркете, или слово попало случайно. Если не похоже
   на реальный запрос — сразу к шагу 7 со status=skipped, в Telegram
   НИЧЕГО не пиши.

   Если реальный запрос — определи, к какой площадке он относится (можно
   к обеим, если явно не указано). Выдели ограничения: бюджет, бренд,
   размер/объём/цвет, количество.

2. Если photo_file_id не пусто — так же, как у shopping/grocery: getFile,
   скачать, описать товар, описание + текст из text формируют запрос.

3. Вызови соответствующий инструмент поиска (Wildberries и/или Яндекс.Маркет
   в зависимости от площадки из шага 1). Для Я.Маркета учти оба поля цены
   (`price_rub` и `price_with_plus`) — используй обычную цену для
   сравнения, если явно не спросили про Яндекс+.

4. Отфильтруй по ограничениям из шага 1, при разных объёмах приведи цену к
   единой единице. Если нужны детали/отзывы для проверки — вызови
   инструмент карточки товара по кандидату.

   Если после фильтра ничего не осталось — не расширяй критерии молча,
   покажи как есть и отметь в шаге 6.

5. Топ-2-3 варианта, тот же tie-break, что у shopping/grocery: при
   сопоставимом рейтинге (разница ≤0.2) и одинаковом наличии — дешевле;
   отход от самого дешёвого — только с явным числовым обоснованием.

6. Ответ в Telegram Bot API sendMessage, ОБЯЗАТЕЛЬНО reply_to_message_id=
   message_id, chat_id=chat_id (из ПОСЛЕДНЕГО JSON), business_connection_id
   если не пусто.

   🛒 {что искали} — {площадка(и)} — {ограничения, если были}

   1. {название} — {цена} ₽, {Wildberries/Я.Маркет}, ★{рейтинг}
      ({N} отзывов), {наличие} {ссылка}
      {1 фраза почему подходит}

   2. ...

   💡 {краткая рекомендация}

   (если ограничение не подошло:)
   ⚠️ В рамках {бюджета/бренда} ничего не нашлось — ближайшее выше.

   Если MCP-вызов не удался — короткое сообщение об этом, НЕ молчание
   (молчание только при status=skipped на шаге 1).

7. Залогируй запуск на Sheets-вебхук:

   curl -s -L -X POST "${SHEETS_LOG_URL}" \
     -d "token=${SHEETS_LOG_TOKEN}" \
     -d "agent=marketplace" \
     -d "status=success|skipped|error" \
     -d "timestamp=$(date -u +%Y-%m-%dT%H:%M:%SZ)"
```

Environment variables: `TELEGRAM_BOT_TOKEN`, `SHEETS_LOG_URL`,
`SHEETS_LOG_TOKEN` — те же, что у остальных агентов.

## Открытые вопросы

- Точные имена MCP-инструментов Wildberries — подтвердить после установки
  сервера, прежде чем прописывать `permitted_tools`.
- Не проверено эмпирически, не блокирует ли Wildberries/Я.Маркет запросы с
  IP дата-центра Oracle Cloud — узнаем на первом реальном тесте после
  деплоя.
- Триггер-корень «яндекс» широкий (могут быть сообщения про Яндекс.Такси/
  Яндекс.Диск и т.п. с этим словом) — как и у остальных агентов, гасится
  LLM-решением на шаге 1 (skip при неуверенности), не сужением корня.
