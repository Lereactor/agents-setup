# Дизайн: вкладка «Мои агенты» в ai-agent-live

Дата: 2026-10-04
Статус: дизайн согласован, реализация не начата

## Цель

Показать реальных Telegram-агентов (`news-digest`, `watchdog`, `shopping`,
`grocery`) в приложении `ai-agent-live` — **онлайн** (видно, что агент работает
прямо сейчас) и **исторически** (вся история запусков) — максимально прозрачно
и красиво. Демо-pipeline Supervisor → Writer остаётся как есть на вкладке «Демо».

## Источник данных

Агенты — облачные Routines, локально их не видно. Единственный общий источник —
Google Sheet-лог (`scripts/log-sheet.gs`, веб-хук Apps Script), который уже пишут
`news-digest`, `shopping`, `grocery` (на 2026-10-04 — 125 строк). Внутренние шаги
агента (рассуждения, вызовы инструментов) в логе не появляются и не будут видны.

### Новый формат лога

Лист `log`: `timestamp_utc | agent | status | detail | run_id`

- `status`: `started` | `success` | `error` | `skipped`
- `detail`: одна строка ≤200 символов — что попросили и что сделано / почему
  ошибка; у watchdog — вердикт. Apps Script обрезает и убирает переводы строк.
- `run_id`: генерируется агентом в начале запуска
  (`RUN_ID=$(date -u +%Y%m%dT%H%M%SZ)-$RANDOM`), пишется в обе записи — по нему
  `started` склеивается с итогом и считается длительность.
- Старые строки (3 колонки) остаются: считаются завершёнными запусками без
  `detail` и без длительности.

### Изменения в агентах (промпты Routine, вставляются вручную)

- Все 4 агента: запись `started` первым шагом, итог — последним (тот же `RUN_ID`,
  плюс `detail`).
- `watchdog`:
  - теперь логирует себя (`agent=watchdog`, `detail` = вердикт);
  - считает только итоговые статусы (`started` не считается запуском);
  - новая проверка: `started` старше 30 минут без итога с тем же `run_id` →
    строка «завис запуск» в отчёте.
- Попутно: выяснить, почему `news-digest` с ~29.09 часто логируется дважды за
  утро с разницей 10–15 с (два расписания или повторная доставка).

## Архитектура

### Backend (`ai-agent-live/backend`)

- `GET /my-agents/log` — читает веб-хук (`SHEETS_LOG_URL`, `SHEETS_LOG_TOKEN` в
  `backend/.env`; токен не уходит в браузер), `follow_redirects=True`.
- Нормализует строки в список запусков:
  `{run_id, agent, status, started_at, finished_at, duration_s, detail}`;
  `status=running`, если есть `started` без итога; `stale`, если такой запуск
  старше 30 минут. Старые строки без `run_id` → отдельный запуск каждая.
- Кэш 8 с. Ответ Google не JSON → один повтор через 5 с; если снова неудача —
  последние удачные данные с `stale_data: true` и временем получения.
- Не настроены переменные → понятная ошибка `not_configured`, вкладка показывает
  инструкцию, а не падает.

### Frontend (`ai-agent-live/frontend`)

- Переключатель вкладок «Демо» / «Мои агенты» в TopBar.
- Опрос `/my-agents/log` раз в 30 с; новые и изменившиеся запуски определяются
  сравнением с предыдущим ответом по `run_id`/статусу.

## Внешний вид («пульт управления», тёмная тема)

- **Граф**: Telegram → Worker → `shopping` / `grocery`; ⏰ 08:00 → `news-digest`;
  ⏰ 09:00 → `watchdog`; пунктир от `watchdog` ко всем агентам («наблюдает»).
- **Карточки-иллюстрации** (inline SVG + CSS-анимации, без внешних ассетов):
  - `shopping` — сине-жёлтая палитра Ozon/Я.Маркета, пакет, при запуске
    выпрыгивают ценники; последний `detail`.
  - `grocery` — зелёная палитра ВкусВилла, корзинка, падают овощи, качаются
    листья; последний `detail`.
  - `news-digest` — газета на фоне восхода, бегущая строка.
  - `watchdog` — щит с вращающимся лучом радара; последний вердикт.
- **Онлайн**: `running` → карточка «⏳ работает…» + запрос + таймер, по рёбрам
  непрерывно бегут частицы. Итог → вспышка цветом статуса (зелёный / красный /
  серый). `stale` → янтарный «завис?».
- **Нижняя панель**: тепловая карта 30 дней (агенты × дни, яркость = число
  запусков, красная точка = была ошибка) + лента истории с `detail`, фильтрами по
  агенту/статусу и поиском.
- **Клик по агенту** → панель: доля успехов, спарклайн запусков по дням,
  средняя длительность, последние 10 запусков с `detail`.
- **«Проиграть историю»**: таймлапс выбранного периода (сутки / неделя / месяц) за
  ~30 с — частицы и вспышки в реальном порядке запусков.

## Проверка

- Backend: юнит-тесты нормализации (старые строки, пары started/итог, `running`,
  `stale`, мусорный ответ Google) + прогон на реальном логе.
- Анимации: фиктивные записи `started → success` / `started → error`, подаются
  только во frontend (dev-режим), в реальный лог не пишутся.
- `tsc -b` + запуск через `start_windows.bat` и просмотр в браузере.

## Ручные шаги пользователя (подробно — в SETUP-GUIDE после реализации)

1. Apps Script: вставить новый `log-sheet.gs` → **Deploy → Manage deployments →
   ✏️ Edit → Version: New version → Deploy** (URL не меняется).
2. В листе `log` дописать шапки `detail` (D1) и `run_id` (E1).
3. Вставить обновлённые промпты в 4 Routine.
4. **Run now** у `news-digest` → убедиться, что запуск виден на графе онлайн.
